1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Jules OS was successfully designed and developed as a hyper-minimalist,
indestructible, and ultra-fast operating system. It bypasses traditional
bloated init systems and boots directly into a custom, highly optimized
C++ Shell ("The Jules Shell").

Key Design Philosophy:
- "No Simulation": Runs a real Linux Kernel (Alpine virt-kernel base).
- "Invisible Bootloader": Syslinux configured to boot silently and instantly.
- "Indestructible": Utilizes an immutable OverlayFS/initramfs architecture.
- "Self-Repairing": A simple reboot wipes all system modifications, restoring
  the OS to its pristine state.
- "Data Safe": User data (/home) is stored on a separate, persistent virtual
  drive (data.img) that survives system resets and crashes.

--------------------------------------------------------------------------------
2. TECHNICAL ACCOMPLISHMENTS (50-Step Roadmap Initiated)
--------------------------------------------------------------------------------
* THE JULES SHELL (C++):
  - Compiled statically via CMake.
  - Replaces /bin/sh and /sbin/init (runs as PID 1).
  - Features dynamic, colorful prompts inspired by CachyOS.
  - Built-in commands: `help`, `status`, `boost`, `python`, `update`.

* THE BOOST MODE:
  - Command `boost` instantly drops RAM caches (PageCache, dentries, inodes)
    via /proc/sys/vm/drop_caches.
  - Attempts to force the CPU scaling governor to 'performance' mode.
  - Ensures the OS runs flawlessly even on devices with < 512MB RAM.

* AUTOMATED BUILD SYSTEM (build.sh):
  - Automatically fetches the Alpine minirootfs and virt-kernel.
  - Compiles the C++ Shell.
  - Injects custom init scripts (init.sh).
  - Packs the rootfs into a bootable initrd.img.
  - Uses xorriso and syslinux to generate `JulesOS.iso`.

* SMART LAUNCHER (boot.sh):
  - Detects host architecture (ARM vs x86_64) to apply correct QEMU emulation
    or hardware acceleration (KVM/HVF) flags.
  - Generates the 1GB persistent `data.img` automatically.
  - Launches QEMU entirely headless (-nographic) for perfect integration
    into Termux TTY environments.

--------------------------------------------------------------------------------
3. FUTURE ROADMAP (Phase 2 & 3 Foundations Laid)
--------------------------------------------------------------------------------
- The QEMU launcher is prepared for future graphics hooks (-vga virtio)
  when a GUI or Desktop Environment ("Jules DE") is introduced.
- The C++ Shell is designed modularly to easily integrate offline AI assistants
  or voice control in the future.
- The A/B partition fallback mechanism is conceptually mapped for OTA updates.
