# Learning\n\n- When building the `aarch64-unknown-linux-musl` target via `cross` (as configured in `.github/workflows/build.yml`), avoid explicitly setting the linker (`CARGO_TARGET_AARCH64_UNKNOWN_LINUX_MUSL_LINKER`) to a GNU GCC binary (`aarch64-linux-gnu-gcc`). The `cross` container already uses the appropriate pre-configured musl compiler suite. Overriding it causes linker missing errors (`os error 2`) and build failure.
- Added root=/dev/ram0 rw to Universal ISO GRUB config and -boot d to the QEMU test command, fixing the VFS unable to mount root fs kernel panic in the boot validation step.
- In '.github/workflows/build.yml', ensure that the 'cross' executable is installed in all jobs that invoke it (e.g., both the 'build' and 'test' jobs), otherwise the workflow will fail with 'cross: command not found'.
- QEMU boot validation deadlocked with `Kernel panic - not syncing: System is deadlocked on memory` when the boot test under-provisioned VM runtime settings and then attempted to boot potentially inconsistent images after desktop package-install warnings; fix by enforcing `-m 1024M -smp 2 -accel tcg,thread=multi`, adding `panic=1 loglevel=7 ignore_loglevel` kernel params for fast/diagnosable panic exits, adding pre-boot workflow resource diagnostics, and failing `scripts/build.sh` immediately when desktop package installation fails to avoid partially installed rootfs.
- CI failed in `scripts/build.sh` because the desktop-install error path called `fail "..."` even though no `fail()` helper exists (the script defines `error()`). This produced `line 319: fail: command not found` and exit code 127, masking the intended controlled abort. Fix: replace `fail` with `error` so desktop package install failures terminate cleanly with the expected `[FAIL]` message and non-zero exit.
